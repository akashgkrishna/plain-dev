Three tiny programs to start with

Before any theory, here are the three most common shapes. Each one does something simple with a list of 5 items.

O(1)Grab the first item

int first = list[0];

1 step, no matter how long the list is.

O(n)Print every item

for (int x : list) {
    print(x);
}

5 items means 5 steps. 1,000 items means 1,000 steps.

O(n²)Print every pair

for (int a : list) {
    for (int b : list) {
        print(a, b);
    }
}

5 items means 5 × 5 = 25 steps. 1,000 items means 1,000,000 steps.

That is the whole idea. Big O just names how the number of steps grows as the list grows.

What is Big O notation in simple terms?

It describes how the work (time) or memory (space) your code needs grows as the input grows. We use n for the number of items, and ignore small details like constants.

O(1)Look at one bill. Same work for any pile.

O(log n)Search a sorted ledger by halving it each time. A million entries takes about 20 steps.

O(n)Check every bill once.

O(n log n)Sorting the bills.

O(n²)Compare every bill with every other bill.

See O(log n) in action: binary search

The list is sorted. Pick a number and press Next step. Each check throws away half of what is left.

How do I find the complexity of code?

1. Count the loops over the input. One loop is O(n). A loop inside a loop is O(n²). Halving each step is O(log n).

2. Loops in a row add, loops inside loops multiply. Two separate loops are O(n) + O(n), still O(n).

3. Drop the small stuff. O(3n) is O(n), and O(n² + n) is O(n²).

What is space complexity?

Same idea, but for extra memory. A few variables are O(1). A new list as long as the input is O(n).

You can often spend memory to save time. To find a duplicate, comparing every pair is O(n²) time. Remembering what you have seen in a set is O(n) time with O(n) extra memory.

Set<Integer> seen = new HashSet<>();
for (int x : list) {
    if (seen.contains(x)) return true;
    seen.add(x);
}
return false;

Frequently asked questions

What is the difference between time and space complexity?

Time complexity is how the number of steps grows with the input. Space complexity is how much extra memory is needed as the input grows.

Is O(n²) always bad?

No. For small inputs it is fine. It becomes a problem when the input is large, because the work grows very quickly.

Do I need maths to understand Big O?

No. Count the loops and ask whether the work grows slowly, steadily or explosively.

Why do interviewers ask about it?

They want to know you can spot slow code and suggest a faster approach, for example by using a hash set instead of a nested loop.
